## Target and annotation contract

The approved target is P(private server). Only affirmative private-server evidence may raise it; no official-Tibia predictor rewards, language/gameplay effects, image inputs, per-channel decisions, displayed indeterminate state or inference abstention. The approved default proposal is P(private)=1%, displayed complement99%. Model choice, context learner, coefficients and hiding threshold belong to milestone B after label review. This packet does not implement them.

Labels here are annotation metadata, not extension states. A missing target label means the source cannot establish the true session and the example must not silently become a negative training label. It does not propose displaying an unknown state.

- `proposed_context`: session, promotion, negation, comparison, unresolved context, or no server evidence. Session/promotion refers to the selected mention, not every word in the title. Several cards have separately annotated secondary mentions.
- `proposed_referent_private`: whether the named project is independently identified as private/derived, separate from what the broadcaster is playing. Unverified referents remain explicit.
- `proposed_stream_private`: proposed private / not_private / missing target. These are assistant annotations awaiting human approval, not new authoritative ground truth.
- `proposed_affirmative_private_evidence`: proposed applicability of the private evidence for the selected mention in this input. Missing evidence-applicability labels stay missing, never negative supervision. A known-private example can have no observable evidence. A comparison can mention a real private server without asserting the current session.
- `active_session_independently_verified`: false throughout this packet. No video or image was inspected by the assistant; two specific labels now have direct maintainer adjudication recorded separately; captured metadata and operator/catalogue facts do not independently prove the live session. Official-world self-declarations are negative-label proposals only, never model features.
- Two records have `approval=maintainer_confirmed`, the other 219 have `approval=pending`, and every record still has `use_in_training=false`. Unreviewed examples outside this sample have no new labels. Original labels are preserved in place and copied only as historical assertions.

## Review decisions that matter

1. **Primary launch presentation vs incidental advertising.** Dedicated private-server launch/beta broadcasts are proposed private as requested, even if no game session has opened. An advertisement embedded in an explicitly different session is not. This is a proposed content-scope interpretation requiring review, not a claim of observed connected gameplay.
2. **Server commands are not all the same.** `WAR?? ... | !rubinot` has a proposed session-positive label grounded in the user example. The maintainer has now resolved raw1400:16 as session-positive and supplied a real nonprivate sponsor-list contrast. Thirteen analogous labels have been revised as explicit pending proposals under that criterion, with their old labels retained in review_history; they are not direct maintainer confirmations. Other captured rows remain pending. Nothing is propagated by channel. Generic commands are neutral. The approved context distinctions will supervise a learner; no decision rule or context learner has been implemented.
3. **Truth with no evidence remains truth with no evidence.** audit:7 records historical maintainer confirmation of RubinOT while the captured title/tags contain no private identifier. Proposed target is private, affirmative evidence false. Do not replace that target or teach MS/levels/language as a shortcut. The fixed low-evidence baseline necessarily misses such cases and cannot be globally calibrated if these hidden positives are common; milestone B must measure this openly.
4. **New-server wording is not unique to private servers.** User opening/protocol/OT-name examples are positive evidence proposals. cases:46/audit:260 provide official new-world counterexamples; protocol-history commentary and incidental launch advertising are controlled negative contrasts. Novel-name behavior must be learned from these distinctions, not a blanket `new server` rule.
5. **Target scope.** PKA/PXG/Baiak/Poke Idle are included per explicit instructions. They are not assumed to be in classic OT catalogues. Medivia is an independent non-CipSoft MMO: audit:213 is a proposed private-family inclusion needing approval. Standalone games such as Project Zomboid are proposed not-private under the replacement target, not positives merely because they are not Tibia.
6. **Catalogue names can collide.** Official Antica/Refugia names also appear in independent private projects. A bare copied name does not identify which project is meant. Full private endpoints, OT/project names, protocol and scoped opening declarations are separate facts. No approved alias table is being shipped.
